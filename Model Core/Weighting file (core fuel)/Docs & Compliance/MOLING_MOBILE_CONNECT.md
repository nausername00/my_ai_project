# 墨灵 · 手机端连通检查清单

> 登记：2026-10-20 ｜ 手机端连通（第一梯队）收尾文档
> 结论先行：**后端 API 层与 APK 均已按设计验证通过**（CORS/CSRF 本地模拟全绿）；
> 真机失败几乎都发生在"环境层"，按下面清单逐层排查即可。

## 一、前提：必须用「启动手机端.bat」启动后端

| 启动方式 | 监听地址 | 手机能否访问 |
|---|---|---|
| `启动手机端.bat`（推荐） | `0.0.0.0:8000`（+ 自动生成/复用 token） | ✅ 可访问 |
| 其他方式（双击别的启动器 / 手动 py） | 默认 `127.0.0.1:8000` | ❌ 手机连不上（"Failed to fetch"） |

> 该 bat 已修复为 GBK 编码（2026-10-20 确认），不再出现乱码报错。
> 首次运行会生成 `mobile_token.txt` 并显示局域网访问地址。

## 二、手机端三种打开方式

1. **手机浏览器（免 token）**：手机浏览器打开 `http://<电脑IP>:8000/v1/mobile/`
   - 同源访问，后端自动放行，无需 token。
2. **墨灵 APK（需填服务器地址 + token）**：设置 ⚙ 里填
   - 服务器地址：`http://<电脑IP>:8000`
   - API Token：`mobile_token.txt` 内容（首次启动 bat 自动生成）
3. **（远期）PWA 添加到主屏幕**：HTTP 局域网下 Service Worker 不注册，暂不可用。

## 三、分层排查清单（自上而下）

| # | 检查 | 方法 | 通过标志 |
|---|---|---|---|
| 1 | 手机与电脑同一 WiFi | 手机设置看 WiFi 名 | 同一网络 |
| 2 | 后端以 0.0.0.0 启动 | 看启动 bat 窗口 | 窗口显示"监听 0.0.0.0:8000" |
| 3 | 电脑 IP 可达 | 手机浏览器打开 `http://<电脑IP>:8000/health` | 看到 JSON（服务正常） |
| 4 | Windows 防火墙 | 首次用 bat 启动时弹窗选**允许**；已拒绝则到「Windows 安全中心→防火墙→允许应用」加放行 python | 第 3 步能打开 |
| 5 | API Token（APK/远程才需要） | 设置 ⚙ 填 token | 对话返回正常回复 |
| 6 | 手机页「连接自检」 | 设置面板 →「测试连接」 | 显示分层提示，按提示修 |

**手机页内置「连接自检」**（2026-10-20 新增）：一键探测电脑后端，并区分
网络不通 / 后端未启动 / 防火墙拦截 / token 错误，直接给出对应修复提示。

## 四、真机验证记录（用户侧）

- 2026-10-19～20：APK 安装后曾出现 `请求失败（http200）`、`Failed to fetch`、
  `cross-origin browser requests are not allowed`。
- 本地核验（2026-10-20）：后端 CORS/CSRF 行为全部符合设计——
  手机浏览器同源放行 ✅、APK WebView（capacitor://localhost）跨源+token 放行 ✅、
  恶意跨源 POST 403 ✅、预检 204 ✅、恶意预检 404 ✅。
- 结论：API 层无缺口；APK 已重打包含最新前端（连接自检）。
  剩余变量 = 环境层（清单 #1–#5），请按表实测一轮。

## 五、已知限制（诚实披露）

- **HTTP 局域网**下：系统通知、语音输入/识别、Service Worker 离线缓存**不可用**
  （浏览器安全策略要求 HTTPS 或本机 localhost）。这是浏览器限制，非墨灵 bug。
- "不用重装包、App 内更新"依赖 Service Worker（PWA 更新机制），HTTP 局域网下不可用；
  该能力在**HTTPS 部署**（T4 自签证书 + 手机信任证书）下才生效，列入远期。
- 公网/异地访问（回国场景）需 Tailscale/ZeroTier 等组网，见 roadmap 远期登记。
