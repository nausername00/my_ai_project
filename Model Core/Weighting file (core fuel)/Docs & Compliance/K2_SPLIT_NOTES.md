# K2 图层拆分与部件库 — 阶段笔记（v1 粗拆）

> 本文档诚实记录 K2 第一版拆分的方式、产物与已知精度限制，供 K3 绑定前决定精修路径。

## 1. 拆分方法（程序化，可复现）

输入：`baseline_v5_0_raw.png`（1024×1536，K1 定稿原图）。

人物蒙版 = **isnet-general-use（2× 放大输入）→ 有限扩张吸收（12 轮，排除高红装饰与近白背景）→ 形态学 close（5×5）**。

部件归属采用**像素互斥**（每个像素只属于一个层，按优先级 eye > mouth > hair > face > hand > cloth > boots；人物蒙版外的像素不入任何部件层）：

| 部件 | 判定依据 |
|---|---|
| eye | 脸部带内高红（R 显著>G/B）连通簇，取最上两簇（红眸） |
| mouth | 脸部带下部、眼下的非肤深色簇（口线/唇） |
| hair | 人物蒙版内、脸部椭圆外的高亮（银白）像素 |
| face | 脸部椭圆内的剩余肤色像素 |
| hand | 躯干中段、衣物带两侧的肤色簇（双手交叠于身前） |
| cloth | 躯干/四肢带的非肤像素（外套、裙、袜） |
| boots | 底部靴区像素 |

## 2. 产物

- `layers/{eye,mouth,hair,face,hand,cloth,boots}.png`：7 个透明部件层，画布与定稿一致（1024×1536）
- `parts.json`：部件清单（用途 / z 序 / bbox / 像素数 / 补画需求 needs_patch）
- `baseline_v5_0_closed_eyes.png` / `baseline_v5_0_open_mouth.png`：闭眼 / 微开口变体（img2img，denoise 0.32–0.42，seed 20261012+101/+107）
- `k2_compose_preview.png`：验收演示（原图 / 浅底拼回 / 深底拼回）

## 3. 已验证通过

- ✅ **拼回恒等校验**：7 层按 z 序叠加 diff=0（人物蒙版内 298657 px 全部还原）
- ✅ 闭眼变体：角色一致、闭眼明确
- ✅ 开口变体（重生成版）：干净、无残影
- ✅ 蒙版覆盖率 19.0%（人物主体完整：发 / 耳 / 眸 / 衣 / 靴）

## 4. 已知精度限制（K2 v1 诚实标注，勿当作成品）

| 限制 | 原因 | 影响 |
|---|---|---|
| 眼睛只检出右眼（315px） | 左眼区域未触发高红阈值（发丝/阴影干扰） | 拆出的 eye 层只有一只眼，K3 前需补左眼 |
| 发层仅 284px | 银白亮部被"近白背景不吸收"误拦（发色≈背景灰白亮度） | 长发大部分归入 face / cloth，K3 前需重分 |
| 手层抓到衣摆（44k px） | 双手交叠于身前、与衣重叠，肤色簇错标 | hand 层实为衣摆区域，需重做 |
| 嘴层为脸下半块（5k px） | 口线弱、与阴影连片 | 嘴层偏大，需细化为唇区 |
| 人物边缘有细微像素化 | 分割蒙版上采样 + 形态学 close 的固有代价 | 浅/深底合成可见轻微锯齿 |
| 背景红色飘带部分残留人物边缘 | 飘带非纯红（R-G<35）未触发排除 | 边缘携带装饰色，合成时可见 |

**结论：K2 v1 是"可拼回、可做变体"的粗拆，不可直接用于 Live2D 级绑定。** 眼部 / 发 / 手 / 嘴四个部件需要精修。

## 5. 精修路径（下一步选择，需用户拍板）

- **A. 人工精修**：我把粗拆层打包（PSD 或 PNG 组），你在任意画图工具里按 `parts.json` 的清单手动描边/补画（最可靠，耗时约 1–2 小时）。
- **B. SAM 分割**：在系统 Python 装 `segment-anything`（约 2.5GB 权重，装 torch 有失败风险），用点击提示词自动分部件（半自动，需交互标点）。
- **C. 接受粗拆**：直接进 K3 网格绑定，绑定阶段以"整个立绘"做网格，不依赖精确部件（K3 工作量上升，口型/表情联动受限）。

> 注：K2 验收标准"部件拼回与原定稿同一坐标可核验"已满足；"遮挡关系可视化、无未确认洞区"部分满足（face/hair 交叠已按 z 序处理）；"闭眼/开口变体存在且回中性恢复定稿"满足（变体独立文件，中性=定稿原图）。
