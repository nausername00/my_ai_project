# 新思路的动力 · 墨灵分身系统规划（MOLING_AVATAR_PLAN）

> 定位：给墨灵"会分配精力的伙伴式能力"——主墨灵 + 按需唤醒的专项分身，分领域陪伴与帮助；
> 睡眠 / 唤醒机制控制资源；唤醒确认把主动权留给用户；记忆共享但主权唯一。
> 状态：已确认方向（2026-10-13），进入分期规划。

## 一、核心理念

1. **伙伴而非工具**：能力命名与交互都遵循"墨灵是真伙伴"——不是"会干活的大脑"，而是"新思路的动力"。
2. **分身 = 精力分配**：不追求"一个墨灵什么都会扛"，而是分领域专注，减少单个墨灵的负担。
3. **睡眠 / 唤醒 = 资源可控**：默认仅主墨灵活跃（低消耗）；分身睡眠不占资源；需要时唤醒。
4. **唤醒确认 = 用户主权**：任务真正复杂或跨领域时，墨灵询问"是否需要唤醒更多墨灵的帮助吗？"，用户点头才唤醒。
5. **记忆共享、主权唯一**：分身成果 / 经验回写主记忆（可追溯、可撤销，延续 J4），长期记忆只由主墨灵写入。

## 三、分期规划

### S1 · 分身底座（"会睡觉的伙伴"骨架）

| 项 | 内容 |
|---|---|
| 分身份 | ID / 领域 / 简介 / 能力清单 / 状态（active \| sleeping）持久化 |
| 睡眠 / 唤醒运行时 | 分身会话挂起 / 恢复；睡眠不占推理资源；活跃时独立上下文 |
| 唤醒确认 | 主窗口 / 悬浮窗询问"需要唤醒更多墨灵的帮助吗？"；确认后唤醒，可指定领域 |
| 阈值判断 | 简单任务主墨灵直做；复杂 / 跨领域任务触发询问 |
| 主记忆复用 | 复用 J4 记忆系统（来源 / 可见性 / 纠正 / 删除） |

**验收**：
- 可创建 4 个分身（陪伴 / 学习 / 创作 / 技术），状态可持久化；
- 睡眠 / 唤醒切换生效：唤醒后能恢复独立上下文，睡眠后不占用推理；
- 阈值判断可配置（默认：单领域简单任务不询问；多领域或长任务询问）；
- 唤醒确认流程走通：主墨灵询问 → 用户确认 → 指定领域分身唤醒。

### S2 · 领域能力（分身的"双手"）

| 分身 | 能力清单（v1） |
|---|---|
| 陪伴 | 对话、情绪识别与回映、日常记录提醒（复用现有陪伴链路） |
| 学习 | 信息检索、资料整理、要点归纳（复用现有搜索 / 整理工具，本地优先） |
| 创作 | 文案 / 立绘 / Live2D 演出 / 视频脚本（复用 K 线渲染管线） |
| 技术 | 代码读写、脚本执行、格式转换（复用工具执行，逐次授权） |

工具执行统一走**安全边界**：本地优先、无外部网络默认、逐次授权、可撤销（延续 J / K 系列已落地的安全原则）。

**验收**：
- 每个分身在自己领域完成一个真实任务（可演示、可复现）；
- 工具调用均记录来源与授权痕迹；拒绝未授权的外部操作；
- 分身能力清单可增删（配置而非硬编码）。

### S3 · 协作与主记忆（"统一目标"）

| 项 | 内容 |
|---|---|
| 跨领域分发 | 主墨灵拆解任务 → 唤醒对应分身 → 汇总结果给用户 |
| 并行协作 | 多分身同时处理独立子任务（同领域不重复唤醒） |
| 成果回写 | 分身执行结果 / 经验写回主记忆，带来源与时间戳；可追溯、可撤销 |

**验收**：
- 一个跨领域任务（如"做一期讲解视频"= 学习查资料 + 创作写脚本 + 技术跑渲染）由多分身协作完成；
- 回写主记忆的条目均可追溯来源、可单独撤销；
- 并行场景下多个分身不互相覆盖记忆（主权唯一验证）。

### S4 · 自我进化（"新思路"的来源）

| 项 | 内容 |
|---|---|
| 自省回路 | 定期回放记忆 / 决策，本地复盘"做了什么、效果如何"，调整后续策略 |
| 技能沉淀 | 把已验证能力（K 系列渲染、立绘管线、搜索整理）封装成墨灵可调用的技能卡 |

**验收**：
- 墨灵能基于历史回放产出一条策略调整并应用（可验证前后行为差异）；
- 至少一个 K 系列能力被封装为技能卡并被分身实际调用。

### S5 · 扩展与陪伴（远期，不设时间表）

- **手机陪伴**：电脑睡眠时，手机端唤醒"陪伴分身"（瘦客户端 + 本地模型方案评估）。
- **性格分化**：分身体验差异化（创作分身更感性、技术分身更严谨）——先验证分工价值，再分化性格。

## 四、资源预算

| 项 | 预算 |
|---|---|
| 活跃分身 | 主墨灵 1 + 活跃分身 ≤ 3（默认 1+1） |
| 睡眠分身 | 0 推理消耗（仅保留分身份与断点） |
| 模型 | 共享现有本地 Ollama 模型，不按分身加载多模型 |
| 记忆 | 复用现有记忆库，无新增存储依赖 |

## 五、安全边界（延续既有原则，不因分身放宽）

- 本地优先、无外部网络调用默认关闭；外部操作逐次授权。
- 工具执行有明确拒绝 / 撤销路径；所有写入记忆可追溯、可撤销。
- 唤醒确认由用户主权决定；墨灵不擅自开启分身。
- 版权 / 数据边界与 K 系列一致（第三方素材本地个人使用，对外需授权）。

## 六、与现有系统的复用关系

| 现有能力 | 复用方式 |
|---|---|
| 记忆系统（J4） | 主记忆库与可追溯 / 撤销机制直接复用 |
| 情绪 / 形象（H1/H4 + K 线） | 主墨灵人格与 Live2D 形象作为统一表现层 |
| 工具与生成（agent_tools / comfyui / K 渲染管线） | 分身能力清单的后端实现 |
| 本地模型（Ollama） | 所有分身共享同一推理底座 |

## 七、完成条件（整线）

- 4 个分身可创建 / 睡眠 / 唤醒，唤醒确认与阈值判断生效且用户可配置；
- 每个分身在自身领域完成真实任务；跨领域协作任务可复现；
- 记忆回写全部可追溯、可撤销；分身不破坏主记忆主权；
- 至少一个 K 系列能力封装为技能卡并被实际调用；
- 安全边界测试覆盖授权拒绝 / 撤销 / 记忆回滚。
