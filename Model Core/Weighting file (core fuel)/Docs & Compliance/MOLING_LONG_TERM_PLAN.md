# 墨灵长期发展规划与验收清单

> 本文把产品愿景映射到当前源码与可交付阶段。它是工程规划，不代表其中描述的能力已经实现。每个阶段以可运行成果、回归证据、文档和回退路径验收；时间仅作估算，优先级与依赖比日历日期重要。

## 项目愿景

打造一个以个人 AI 伙伴为核心，集情感陪伴、沉浸式体验、游戏互动、创作设计、知识学习、工作自动化和多 Agent 协作为一体的本地 AI 生态系统。以 Windows 11 为首要运行平台，优先利用 Ollama 和本地模型，兼顾可选的外部 AI 服务。让用户拥有多个具有不同个性、专长、记忆和视觉形象的 AI 伙伴，并在用户授权下共同学习、协作、创作和完成任务。

## 长期原则

- **本地优先**：个人资料和记忆尽量留在本机，外部服务由用户选择启用。
- **安全优先**：模型提出建议，受控工具执行操作；权限不能依靠模型自己判断。
- **用户掌控**：用户可以查看、修改、删除、导出自己的数据，也可以关闭主动互动。
- **可验证成长**：通过测试、反馈和成果质量评估技能，不将未经验证的回答自动变成事实。
- **模块化扩展**：伙伴、模型、工具、创作能力和游戏接口均采用清晰的模块边界。
- **可靠优于数量**：优先做好少数真正有用的功能，再增加 Agent 数量和自动化复杂度。
- **尊重用户福祉**：陪伴功能提供支持和选择，不制造情感依赖，也不取代专业治疗。
- **每阶段可交付**：每次开发都应有可运行成果、测试标准、文档和回退方案。

## 产品边界

- Windows 11 为首要桌面平台，本地模型与本机数据优先；配置远端模型时，清楚提示请求可能离开本机。
- 模型只产生建议和结构化请求；文件、系统、网络等副作用必须由独立的受控工具层执行。
- 记忆、外部评议、主动互动、麦克风、屏幕/图片分析、联网和写入权限均由用户明确控制，并可撤回。
- 对话表达不宣称模型有意识或真实情绪；陪伴体验不能替代专业心理或医疗服务。
- 未经测试、用户反馈或可复现证据支持的内容，不自动晋升为事实、技能或长期记忆。

## 阶段 0：基础加固与可复查基线

### 已核验并处理

- `inference.py` 的后端切换类型注解引用了未导入的 `Mapping`，会在导入模块时触发 `NameError`，进而使 API 和多个测试模块无法导入。已补齐导入。
- `floating.html` 的角色更新回调可能在 Live2D 状态初始化前触发；隔离运行该回调的测试也没有声明 Live2D 状态。已将未初始化状态安全地按未就绪处理。
- `avatar_tasks.py` 原先用 `python -c` 执行调用方表达式，并依赖关键词黑名单禁止危险操作。已替换为仅接受数字和有限算术 AST 的计算器；Git 查询参数固定为只读子命令及固定参数，不再透传调用方参数。
- 伙伴任务 API 原先用 `bool(value)` 解释审批字段，字符串 `"false"` 会变成真值。已改成只接受真正的 JSON 布尔值，并新增反例测试。
- 记忆列表将同一秒内新增的条目按随机 ID 排序，可能让最近记忆回退。已改为在时间戳相同时保留 JSON/插入顺序。
- API 工具执行路由检查桌面端 `X-Moling-Tool-Capability`，不能只靠请求体中的 `approved` 字段授予通用工具执行权；该门禁应保留并持续测试。

### 仍需完成

1. 用受控 Windows 环境跑完整 Python、Node、语法和 Electron 冒烟验证；区分代码缺陷、缺少可选依赖、模型未配置和运行环境限制。
2. 审查每条有副作用的 API 路由：方法、参数 schema、调用方身份、逐次审批、目标范围、取消/超时、回读验证、审计字段和错误码。
3. 梳理任意代码执行路径：禁止模型输出直接进入 `eval`/`exec`；命令执行保持固定工具名、参数数组、`shell=False`、可审计白名单与硬超时；逐步移除通用 shell 或将其置于独立 OS 级隔离环境。
4. 收紧 API 默认边界：仅回环绑定；对浏览器可触发的状态变更设置来源/主机校验和请求体大小上限；显式远程监听必须单独配置认证与警告。
5. 增加审计日志字段白名单，确保令牌、API key、完整私人对话、记忆正文、音频和图像不被默认写入日志。
6. 为备份提供完整性校验、保留策略、恢复预览和隔离目录恢复演练；避免恢复覆盖当前数据。
7. 统一测试入口及依赖说明，固定基础 Python/Node 版本；核心测试不依赖 Ollama、网络、语音下载或外部服务。

### 阶段 0 加固落地记录（2026-10-15）

以下把上表 7 项全部处理并登记证据；新增测试 9 项（审计 4 + 备份闭环 5），Python 基线由 448 升至 457。

1. **受控环境验证**：Python 457 通过 / 6 跳过、Node 58 通过、语法检查通过、Electron 真实启动冒烟通过（F1 修复后主进程存活）。
2. **API 副作用路由审查**：do_POST/PUT/DELETE 方法级 CSRF（`_reject_untrusted_browser_origin`，非 `moling://local` 来源 403）；`_read_json` 请求体 1MB 上限；审批/回写字段 `_strict_json_bool` 只接受真 JSON 布尔；工具执行路由 `/v1/agent/tool/execute` 用 `X-Moling-Tool-Capability` HMAC 能力令牌门禁（缺令牌或比对失败即 403，无副作用），并支持 trace 取消/超时；分身 task/execute/writeback 走严格审批；GET 的 social/notify 等敏感读保持 127.0.0.1-only。
3. **任意代码执行路径**：全引擎扫描确认——`avatar_tasks.py` 已改为纯 AST 数值计算器（白名单算子/节点≤64/数值≤1e9/指数≤8）+ git 固定只读参数；`computer_use.py` 全部 `subprocess.Popen` 参数化（`shell=False`、路径经 `safe_relpath` 白名单、超时+取消）；无 `eval`/`exec`/`os.system` 调用（`model.eval()` 为 PyTorch 模式切换，非代码执行）。
4. **API 默认边界**：`app.py` 默认绑定 127.0.0.1；`--host` 非回环时打印醒目认证警告；请求体上限（JSON 1MB、音频 25MB、图片 10MB/尺寸/像素限制）与字段长度限制齐备。
5. **审计日志字段白名单**：新增 `audit.py`（JSONL 追加、5MB 轮转、失败静默、线程安全），只落盘 `ts/method/route/status/duration_ms/error/client` 七字段；`log_message` 占位改为真实审计，`_tracked` 为每个请求记录；白名单不含任何令牌/正文/内容字段名（测试断言）。
6. **备份完整性/保留/恢复**：`backup.py` 新增 `verify_backup`（存在/非空/JSON 可解析）、`restore_preview`（只列不写）、`restore_backup`（默认 dry_run、拒绝覆盖已存在文件、其余照常恢复）、`prune_backups`（保留最近 N 份）；5 项测试覆盖损坏检出/预览/干跑零写入/拒绝覆盖/保留策略。
7. **统一测试入口与版本固定**：新增 `Testing & Evaluation/run_all_tests.bat`（停 8000 → Python 全量 → 语法 → Node，汇总退出码）与 `TEST_BASELINE.md`（OS/Python 3.14.5/Node v22.23.2/Git 2.56/命令/基线/跳过原因）。

### 阶段 0 验收

- 核心 Python 模块可以导入，API 可在隔离测试中启动；单元测试和桌面逻辑测试通过，跳过项逐项说明原因。
- 未提供桌面审批能力令牌时，任何工具执行请求均失败且没有副作用；错误类型、错误路径、越界路径、超时与取消均有测试。
- 恶意或畸形请求无法把模型文本变成任意进程执行；所有进程创建点均有调用者、命令白名单、参数化调用和超时证据。
- 本机 API 不向非本机网卡监听；浏览器跨站请求不能触发状态变更。
- 备份可在干净隔离目录恢复并校验；核心日志不含秘密与个人内容。
- 阶段基线文档记录 OS、Python、Node、依赖、测试数、跳过原因和未覆盖流程，不把历史路线图统计当作当前结果。

## 八大目标 → 模块、任务与验收

### 1. AI 伙伴与长期陪伴

**模块：** 伙伴档案、对话会话、记忆仓库、语音偏好、立绘/表达、记忆控制台。

**任务：** 稳定角色切换和会话生命周期；给每条记忆记录来源、时间、可见范围、确认状态和最后使用记录；支持编辑、删除、导出、暂停注入；为每个角色保存可试听的声音和表达选项；明确短期上下文与持久记忆的区别。

**验收：** 角色切换不会串上下文；私密或删除的记忆不会进入后续提示；关闭记忆后仍可聊天；删除/导出可复核；语音不可用时文本完整可用；单轮纠正不会自动变永久记忆。

**悬浮窗本轮完善（2026-10-19）：** 将默认陪伴态收紧为 300×144，头像互动菜单改成双列紧凑排布；展开态保留 340×640、Live2D、通知和完整菜单。置顶级别从 `screen-saver` 降到普通浮窗级，降低对全屏内容的覆盖干扰；首次出现在主屏幕右下角，展开/收起时重新限制在当前显示器工作区内；从浮窗快捷互动发起聊天后显示并聚焦主窗口，避免消息发送成功但回复留在后台。新增基于显式“模拟状态”的轻柔呼吸光晕，并尊重系统减少动态效果设置；头像菜单现支持键盘 Enter/空格打开、Escape 关闭，且同步无障碍状态。前端语法检查及悬浮窗/布局定向测试已复核。仍需重启应用加载新体验，并在 Windows 11 多显示器、分辨率变化、全屏游戏/演示和窗口恢复场景做实机验收。

### 2. 放松、情绪支持与沉浸体验

**模块：** 场景播放器、环境音资源、呼吸引导、故事状态机、情绪表达适配器、主动提议控制。

**任务：** 场景资源可离线使用、可静音和停止；引导步骤可跳过；主动体验频率、免打扰时段和通知渠道可配置；对高风险表达提供恰当支持并提示专业服务边界；将“模拟状态”与真实情绪识别明确分开。

**验收：** 任一体验可随时暂停/退出；关闭主动互动后没有主动推送；网络断开仍能使用已缓存内容；不将模拟状态表述为诊断、意识或真实情感；情绪支持路径有隐私与误判回归样例。

### 3. 游戏与虚拟世界

**模块：** 小游戏沙箱、文字冒险状态、游戏资料接口、场景/角色编辑器、模组工作区。

**任务：** 对小游戏验证无任意网络、导航、文件和 Node 权限；草案与正式文件隔离；提供修改、重置、丢弃、预览、导出和确认采用；游戏攻略答案区分引用资料与推测。

**验收：** 沙箱限制有自动化反向测试；丢弃草案不改变项目文件；采用前展示差异并保留回退副本；故事状态可保存、重置和导出；攻略注明来源及资料日期。

### 4. AI 创作工作室

**模块：** 创作项目、媒体资源、提示词/配置版本、预览器、差异审阅、导出器。

**任务：** 统一图片、故事、网页、代码、视频素材、设计稿和演示稿项目元数据；将生成物放入隔离草稿；维护版本、素材来源和生成配置；支持用户继续编辑及安全导出。

**验收：** 至少一条从创意、草稿、预览、用户修改到保存/导出的真实流程完整可用；每个阶段有可读状态；失败不覆盖已有成果；项目可重开并复现关键设置。

### 5. 知识、文件与工作助手

**模块：** 文件授权目录、OCR/PDF 转换、文档解析器、个人索引、来源片段、报告导出。

**任务：** 文件只从用户选定目录/文件读取；索引支持重建和彻底删除；答案保存引用文件、页码/片段和生成时间；文档写出采用预览、确认、避免覆盖和回读核验；大文件、坏文件和敏感信息有处理边界。

**验收：** 代表性 PDF/OCR 样本有可核查引用；来源不存在或证据不足时明确说明；删除原文后索引和缓存一并删除；写出前显示目标路径与差异；真实资料测试不依赖外部模型。

### 6. 多 Agent 协作与知识成长

**模块：** 专业角色注册表、任务拆分器、消息信封、结果汇总、评审器、技能库、评估集。

**任务：** 为每个子任务定义输入范围、交付格式、权限和验证条件；外部模型调用前显示服务、精确负载与费用；把其他 Agent 内容当作不可信资料；技能需有测试、版本、来源和撤销机制。

**验收：** 展示任务分工及各自实际输入；关键结果至少有独立验证证据；意见冲突不被多数票掩盖；未授权不发生外部请求；技能升级需通过固定评估集并支持回滚。

### 7. 安全自动化与系统管理

**模块：** 授权/能力服务、任务队列、计划调度器、执行器、审计日志、取消令牌、备份/恢复。

**任务：** 权限按工具、目标、范围、时间和次数颁发；任务状态覆盖待确认、运行、成功、失败、取消和恢复；重试需幂等；为可逆写操作保留撤销信息；系统监控默认只读；异常通知可静音。

**验收：** 未授权、过期授权和跨范围授权均无副作用；重启后运行任务状态可解释；取消结果区分“已请求”与“已生效”；失败步骤可重试或回滚；日志可查但不泄露密钥/内容。

### 8. 开放、可扩展的 AI 生态

**模块：** 插件清单与权限声明、Provider 接口、模型路由、工作流图、场景注册表、兼容性检测。

**任务：** 固定插件 manifest、版本和能力 schema；工具访问由运行时权限控制；模型端点通过适配器接入；工作流以可校验版本保存；插件故障可隔离并可禁用。

**验收：** 新增一个模型、工具和场景分别通过标准接口完成，不需修改核心路由；插件声明权限与实际能力一致；不兼容插件不会启动；升级和卸载可回滚并清除其授权数据。

| 3 工作知识 | OCR、PDF、检索、引用、文件读写与报告生成 | 真实资料可处理；用户能核查来源；删除与导出闭环。 |
| 4 自动化 | 受限工具、定时任务、备份恢复、监控和通知 | 多步骤任务可追踪/取消；失败可恢复；权限作用域可验证。 |
| 5 多伙伴 | 专业 Agent、跨模型评议、交叉验证、技能库 | 可见分工、实际输入与验证证据；未授权外发为零。 |
| 6 生态扩展 | 插件 API、模型 Provider、工作流和多设备接口 | 新能力通过接口接入；权限声明、隔离、升级和回滚测试齐备。 |

## 推荐实施顺序与阶段门

1. 完成阶段 0 剩余安全审查和环境验证，形成机器可重复的基线命令与报告。
2. 先完善伙伴/记忆/API 的边界，再扩充创作、文档或自动化功能，避免将现有不一致复制到新模块。
3. 每项功能先定义数据流和副作用，再定义模块接口与 UI；将危险能力默认关闭。
4. 每个阶段交付包括：功能代码、负向安全测试、用户可见控制、数据迁移说明、操作文档和回退办法。
5. 一个阶段只有在验收清单逐项有证据后才进入下一阶段；时间估算不构成跳过验收的理由。

## 最终成功标准

墨灵不以模型数量、功能列表或界面效果衡量成功，而以以下能力为准：

- 能够长期陪伴，并准确管理用户授权的记忆。
- 能提供放松、游戏和创作体验，而不只是生成文字。
- 能处理真实文件、协助工作，并提供可核查的成果。
- 能将复杂任务拆解，协调其他伙伴，并检查最终结果。
- 能在授权范围内自动执行任务，出错时可追踪、可取消、可恢复。
- 能通过插件与标准接口不断扩展，而不因增加新功能破坏已有功能。

最终目标：把墨灵建设成一个以用户为中心、以 AI 伙伴为交互入口、以本地模型和可扩展 Agent 为能力基础、以安全与用户自主权为底线的个人 AI 生态系统。
